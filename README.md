# Makhzani (مخزني) — نظام SaaS لإدارة المخازن والمبيعات والمشتريات

نظام SaaS متعدد الشركات (Multi-Tenant) لإدارة المخزون، المبيعات، المشتريات، العملاء،
الموردين، الخزينة، والأرباح — قابل للتوسع مستقبلًا إلى ERP كامل.

## حالة المشروع

**Phase 0 حتى 16 مكتملة:** تسجيل الشركات، الدخول، الصلاحيات، عزل البيانات، إدارة الأصناف/المجموعات/
العلامات التجارية/الوحدات/المخازن، محرك حركة المخزون، الموردون والمشتريات، العملاء والمبيعات، مرتجع
المبيعات والمشتريات، التحويلات بين المخازن، الجرد، كشوف حساب العملاء والموردين، إدارة الخزينة الكاملة،
تقرير الأرباح، تقارير تقييم المخزون/الأصناف تحت حد الطلب/المبيعات/المشتريات (كلها قابلة للتصدير CSV)،
ولوحة تحكم رئيسية بمؤشرات أداء حية ورسم بياني تفاعلي للمبيعات والمشتريات (14 يومًا). الاشتراكات والفوترة:
خطط مدفوعة بحدود مفروضة تلقائيًا (Basic/Professional/Enterprise)، منع الإنشاء/التعديل عند انتهاء
الاشتراك، دفع عبر PayPal، ودفع يدوي (فودافون كاش/تحويل بنكي) بإثبات دفع ومراجعة أدمن قبل التفعيل.
PayTabs محجوزة كواجهة بوابة لاحقة (لم تُفعَّل بعد). لوحة إدارة المنصة الكاملة على `/admin/login`:
لوحة تحكم بمؤشرات المنصة، إدارة الشركات (تفعيل/تعطيل — التعطيل يمنع الدخول فورًا حتى لجلسة مفتوحة
بالفعل)، إدارة الخطط وحدودها وأسعارها لكل دولة، مراجعة المدفوعات، وإعدادات أسعار الصرف التقريبية.
Phase 16 — تدقيق جاهزية الإنتاج الكامل: فرض صلاحيات RBAC فعليًا في كل الأكشنز (كان الكتالوج
موجودًا منذ Phase 1 لكن غير مفروض)، حماية من Brute-Force على الدخول (شركات وأدمن)، تصحيح سباق
اعتماد/رفض الدفعات، تحقق من محتوى ملفات الإثبات (Magic Bytes) لا امتداد الملف فقط،
Security Headers + CSP، 43 اختبارًا آليًا حقيقيًا (`npm test`) ضد قاعدة بيانات حقيقية (عزل بين
الشركات، تعطيل الشركة، الاشتراكات، حدود الخطط، حالات الدفع)، وخطة نسخ احتياطي موثَّقة
(`docs/BACKUP_AND_RECOVERY.md`). المشروع بمجمله (Phase 0-16، خارطة الطريق الأصلية كاملة).

**Phase 17** — صفحة هبوط تسويقية احترافية على `/` (بدل التوجيه المباشر لتسجيل الدخول):
عربية RTL بالكامل، صفر مكوّنات عميل تقريبًا (Server Components + `<details>` أصلي بدون
JavaScript لقائمة الموبايل وأسئلة الشائعة)، أسعار وحدود الباقات والفترة التجريبية مسحوبة
حيًّا من نفس قاعدة بيانات الفوترة (بدون أي تكرار للبيانات)، SEO كامل (Metadata/OG/robots/
sitemap)، ومستخدم مسجَّل دخوله يُعاد توجيهه تلقائيًا لـ `/dashboard`. الأداء مؤكَّد فعليًا:
حجم JS للصفحة الرئيسية أقل من `/login` نفسها.

**Phase 18** — تدقيق UI/UX للتطبيق المصادَق عليه وإصلاح أعطال حقيقية: إصلاح عطل حرج كان
يُسقِط الصفحة بالكامل ("This page couldn't load") عند الضغط على اسم المستخدم في الشريط
العلوي (استخدام خاطئ لبنية قائمة Base UI)، وربط قائمة الحساب بصفحة إعدادات فعلية جديدة
(`/dashboard/settings`) بدل زر معطَّل بلا وجهة. عطل ثانٍ مكتشَف استباقيًا أثَّر على 15 ملفًا:
تحذير حقيقي في الـ Console بسبب زر-رابط لا يطابق افتراض Base UI للأزرار — أُصلح مركزيًا في
مكوّن الزر المشترك بدل تعديل كل ملف. عطلان إضافيان في عرض بيانات حقيقية: طريقة استرداد
المرتجعات وبعض القوائم المنسدلة الأخرى كانت تعرض القيمة الخام بدل التسمية العربية قبل أول
فتح للقائمة (نقص `items` في Base UI Select)، وجدول مدفوعات الشركة في لوحة الأدمن كان يعرض
كود بوابة الدفع الخام بدل اسمها العربي. تدقيق منهجي لكل الصفحات المصادَق عليها (تينانت +
أدمن) بلا أخطاء Console متبقية، تأكيد عدم تأثر RBAC/عزل الشركات بعد اختبار حساب بصلاحية
مقيَّدة، و44 اختبارًا آليًا ناجحًا (43 + اختبار بنيوي جديد يمنع تكرار عطل القائمة).

راجع [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) للوثيقة الكاملة (المعمارية، قاعدة البيانات،
الصلاحيات، خارطة الطريق).

## التقنيات

Next.js 14 (TypeScript) · PostgreSQL (Supabase) · Prisma · NextAuth.js · Tailwind CSS + shadcn/ui ·
نشر عبر Vercel + GitHub. الدول المستهدفة أولًا: السعودية ثم مصر (تفاصيل التسعير حسب الدولة في
`docs/ARCHITECTURE.md` §8.2). بوابة الدفع الأولى: PayTabs (تغطي السوقين معًا).
